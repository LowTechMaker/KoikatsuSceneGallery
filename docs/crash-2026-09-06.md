# 2026-09-06 縮圖排程期間的 WinUI 崩潰

## 證據

- Windows Application Error：2026-09-06 12:47:33，PID 32776，`Microsoft.UI.Xaml.dll`，`0xc000027b`。
- 分析本機 `KoikatsuSceneGallery.exe.32776.dmp`；程式已執行約 67 分鐘。
- 當機 UI 執行緒的混合堆疊：`LibraryBrowser.Container_Changing` 的分階段回呼 → `CoordinateGalleryViewModel.RequestThumbnail` → `GalleryViewModelBase.ScheduleThumbnailRequest` → `ThumbnailPriorityScheduler.Enqueue` → `Monitor.Enter_Slowpath` → `CoWaitForMultipleHandles` → `PeekMessageW` → 第二層 WinUI 訊息處理 → `RoFailFastWithErrorContextInternal2`。
- 這是服裝卡縮圖排程鎖定競爭期間的訊息重入，並非已證實的匯入清單錯誤。普通 `crash.log` 沒有捕捉此次原生 fail-fast。
- 小型傾印保存的例外清單含 `0x8000ffff`、`0x80040111`、三筆 `0x80070057`；其延伸資訊頁未收錄，不能將每一筆都判定為本次根因。Microsoft XAML 公開符號下載未完成，原生 XAML 函式名稱沒有完整解析。
- 相同的 Monitor → COM 訊息處理 → WinUI 重入終止機制也見於 [WinUI issue #11099](https://github.com/microsoft/microsoft-ui-xaml/issues/11099)。根因判斷主要來自本機混合堆疊。

## 修復

縮圖排程器的短暫佇列臨界區改用不處理視窗訊息的 `SpinLock`，避免 UI 執行緒進入 `Monitor` 的 STA 訊息等待。臨界區只修改有限容量的記憶體佇列；工作、捨棄回呼與 semaphore 操作均在鎖外，所有退出路徑均由 `finally` 釋放。

不以忽略例外處理原生 fail-fast，也不改變縮圖優先順序、工作數上限或相簿資料。
