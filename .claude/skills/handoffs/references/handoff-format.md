# 交接格式

## 檔名與標題

- 檔名：`docs/handoffs/phase-NN.md`，`NN` 至少兩位數（`phase-07.md`、`phase-121.md`）。
- 第一行：`# 第 N 部分交接：<標題>`。

## 必填內容

每份交接都要有以下內容，沒有東西可寫時寫「無」並說明，不要刪掉該節。

| 項目 | 寫什麼 |
| --- | --- |
| 交接版本 | `- 交接版本：vN`，獨立一行（驗證腳本靠這行判斷目前版本） |
| 日期 | `- 日期：YYYY-MM-DD` |
| 完成範圍 | 這次完成了什麼；使用者的原話或決定可以引用 |
| 改動 | 依功能分段說明做了什麼、為什麼這樣選 |
| 涉及檔案 | 新增、修改、刪除的檔案與各自責任 |
| 保留政策 | 刻意保留的使用者修改、舊行為、舊名稱或相容性 |
| 驗證 | 實際執行的命令與結果（警告數、測試數）；實機驗證的步驟與觀察；**沒有驗證的部分與原因** |
| 請使用者手動確認 | 需要使用者自己操作確認的項目 |
| 尚未完成 | 未做完、被阻擋的事項 |
| 下一步 | 建議的下一個動作 |
| Claude 已讀標記 | 見下方 |

## 已讀欄格式

一行一個版本，必須完全符合此格式（驗證腳本用正規表示式比對）：

```text
- [ ] Claude 已讀 v1（閱讀完成時間：待填；閱讀者／任務：待填）
- [x] Claude 已讀 v1（閱讀完成時間：2026-09-13T10:00:00+08:00；閱讀者／任務：Claude / 任務識別）
```

- 每個版本恰好一條；目前版本（與「交接版本」相同）必須存在。
- 已勾選的欄位：時間須為 ISO 8601 含時區，閱讀者不可為空或「待填」。

## 版本

- 錯字、連結修正：不算實質修訂，版本不變。
- 改變結論、驗證結果、待辦或範圍：實質修訂。版本加一、新增一條 `[ ]` 未讀欄，舊版本的欄位原樣保留。

## 範本

`scripts/New-Handoff.ps1` 產生的骨架就是範本，章節順序以它為準。
